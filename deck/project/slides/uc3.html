USE CASE 3 · FOLLOW UP

Meeting notes to actions, approved by the RM

How it works

1. RM types notes (voice memos from Phase 2)

2. Agent extracts needs, products discussed, risks, commitments and dates

3. Drafts the call report, tasks and a customer email; proposes next-best actions

4. RM edits and approves. Only then does the agent write to CRM and tasks. The RM sends the email.

TARGET

This is the only use case that writes to bank systems, so it is the one where agent design matters most. The agent has two kinds of tools: read tools it can call freely, and write tools that only create a draft. Nothing is committed to the CRM until the RM presses approve, and customer email is always sent by the RM from their own mailbox. This keeps the human accountable and gives us a clean training and evaluation signal: every edit the RM makes to a draft tells us where the model is weak. Next-best actions start as simple, explainable rules plus transaction signals, not a black-box model.
