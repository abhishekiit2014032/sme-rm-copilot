4 · MODEL EVALUATION

Evaluate before release, measure after

Offline · before release

  • Golden set: 300+ questions and 50 briefs, labelled by RMs and credit SMEs
  • Retrieval: recall@8, ranking quality
  • Answers: groundedness, correctness, citation accuracy, correct declines
  • Red team: prompt injection, cross-portfolio requests, PII extraction
  • Gate: groundedness ≥ 0.95 as a 95% lower bound, no regression

Online · in production

  • RM feedback: thumbs up or down with a reason code
  • Draft edits: how much RMs change before approving
  • Sampling: in-region LLM judge on 5% from the audit content store, weekly SME review
  • Signals: decline and escalation rates, tool errors
  • Loop: every failure becomes a new golden case

The LLM judge is calibrated against SME labels and re-checked each quarter; human review settles any disagreement.

Evaluation is how we turn “it seems to work” into evidence a risk committee will accept. Before any release, whether a new prompt, a new model or a re-indexed policy set, the change runs against a golden set built with RMs and credit SMEs, and it cannot ship if any metric regresses. We measure retrieval separately from generation, because they fail in different ways. A red-team set checks the security properties: prompt injection, requests for customers outside the RM’s portfolio, and attempts to extract PII. In production we use cheap, continuous signals: feedback, how much RMs edit drafts, and decline rates, plus sampled LLM-judge scoring with weekly human review. The judge model runs in UAE North and reads the sample from the encrypted audit content store, never from telemetry. The judge itself is calibrated against human labels, so we know how far to trust it.
