Technology choices on Azure and their trade-offs

LayerOptions consideredChoice and trade-off
HostingAKS private cluster or Azure Container AppsAKS, the Bank’s standard: network policy, workload identity, isolated signer and verifier pods. More to run; Container Apps if there is no AKS platform team.

Model versions: the latest GA GPT-class model offered as Regional Standard in UAE North, confirmed with Microsoft before build.

The platform is Microsoft Azure, so the choices here are between Azure options, each with a trade-off we accept on purpose. Hosting: AKS, because the Bank standardises on it and it gives us network policy, workload identity and separate pods for the approval signer and verifier. It is more to operate; Azure Container Apps is the documented alternative if there is no AKS platform team. Models: Azure OpenAI deployments in Azure AI Foundry, as Regional Standard in UAE North so inference stays in the country. Global and Data Zone deployments are cheaper and get new models first, but traffic can be processed elsewhere, so they are ruled out. Provisioned throughput is a gate after the pilot, on measured tokens, not a day-one cost. Orchestration: thin custom workflows rather than Microsoft Agent Framework or Foundry Agent Service. Our use cases have a known shape, and a deterministic workflow is easier to test, trace and explain to model risk; we re-evaluate the frameworks at each phase. Retrieval: Azure AI Search, because policy questions need hybrid keyword and vector search, a semantic ranker, Arabic analysis and hard filters on version and clearance. Cosmos DB vector search or pgvector would mean one service fewer but weaker hybrid relevance. Observability: Application Insights with OpenTelemetry, managed Prometheus and Managed Grafana, carrying metadata only. Prompt and answer content never goes to telemetry; it lives only in the encrypted audit content store, which is also what investigators replay. Exact model versions are confirmed with Microsoft for UAE North before build.
