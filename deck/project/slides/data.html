PRINCIPLE

Customer data is never copied into a vector store. It is read at question time with the RM’s own permissions, so access rules and freshness come from the source system.

Two integration patterns, chosen per data type. Structured customer data (balances, limits, KYC status) is fetched live through APIs, or a read replica where the core system cannot take the load. That keeps it fresh and lets the source system’s entitlements apply. Unstructured, non-customer-specific content (policies, product guides, circulars) goes through an ingestion pipeline into a search index, with version and effective-date metadata. Integration effort is usually the long pole in these programmes, which is why discovery starts with an API inventory: which of these already have usable APIs and which need an ODS or a new service.
