The risks we plan for from day one

The top three risks are trust, data exposure and integration. Trust is managed by the hallucination controls in the deep dive: citations, a groundedness check and a decline path, plus an evaluation gate before any release. Data exposure is managed architecturally, by enforcing entitlements in code and testing it with a red team. Integration is the most common reason these programmes slip, which is why the API inventory happens in week one and the first pilot use case needs no core-system integration at all. Adoption is a real risk too: RMs will not open another app, so the assistant lives in the CRM and Teams, and RM champions help design it.
