Agents on a short leash

One orchestrator, many tools. Not a swarm of agents: easier to test, trace and explain to auditors.

Fixed workflow where possible. UC1 runs a known fan-out of tools; open planning is used only where it adds value.

Budgets. At most 6 tool steps, a time-out and a token cap per request; on overrun it stops and explains.

Writes are proposals. Write tools create drafts. A commit needs the RM’s click, carried as a signed approval token.

We use agents, but we keep them constrained, because predictability matters more than autonomy in a bank. One orchestrator with a typed tool catalogue is easier to test and explain than several agents talking to each other. Where a use case has a known shape, like the pre-meeting brief, we run it as a deterministic workflow and use the LLM only for summarising; free-form planning is reserved for open questions. Every request has a step, time and token budget. The tool table is the security boundary: read tools enforce entitlements in code, and anything that changes data is a draft until the RM approves it. The approval is a signed token the write API checks, so the model cannot approve on the RM’s behalf, even if it is tricked by a prompt injection.
