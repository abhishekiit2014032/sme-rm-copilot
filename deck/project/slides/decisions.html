Five design decisions and what we traded off

DecisionOur choiceAlternativeWhy
GroundingRAG + live tool callsFine-tune the LLMFresh data, citations, access control at source; fine-tune later only for tone or format
Customer dataLive APIs as the RMEmbed it in a vector DBNo PII copy; entitlements and freshness come from the source system
Agent designOne orchestrator, typed toolsMulti-agent frameworkEasier to test, trace and explain to auditors and model-risk teams
Model hostingHosted frontier model, private in-region endpointSelf-hosted open-weights modelBest quality today; the gateway keeps open-weights as an option for volume tasks
Write actionsDraft + RM approvalAutonomous writesKeeps the RM accountable and makes regulators comfortable

These are the decisions an architecture review board will challenge. Grounding: we use retrieval and tools rather than fine-tuning, because policies and customer data change daily, fine-tuning cannot cite its sources, and it cannot enforce access control. Customer data: we query it live as the RM instead of embedding it, so there is no second copy of PII to secure, and access rules come from the source system. Agent design: a single orchestrator with typed tools is less fashionable than multi-agent systems, but far easier to test and explain. Model hosting: a hosted frontier model gives the best quality today; because everything goes through the gateway, we can move high-volume or sensitive tasks to a self-hosted open-weights model later. Writes: a human approves every change.
